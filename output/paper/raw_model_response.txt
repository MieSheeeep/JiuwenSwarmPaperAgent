  "abstract": "This local synthetic pilot examines how different history-selection policies affect a single model's ability to answer questions about configuration state while controlling API token use. Using 24 deterministic synthetic histories and 60 records, we compare four policies: full history, a recent-window baseline, lexical retrieval, and retrieval augmented with summaries. The full-history reference is unbounded, and token counts are proxy estimates from the cl100k_base tokenizer rather than exact model tokens. All policies run in isolated sessions with the same model and deterministic decoding. Observed exact accuracy is 24/24 for full, retrieve, and retrieve_summary, and 6/24 for recent. Paired comparisons show recent is correct only on late-position cases, while retrieve and retrieve_summary match full on every case. Summary costs are included in token accounting. These results are descriptive for a synthetic convenience sample; Wilson intervals are not guarantees, and no equivalence or generalization claim is made. The pilot suggests that lexical retrieval can preserve configuration state at lower proxy token cost than full history in this setting, but broader evaluation is required before any research claim.",
  "introduction": "Agents that operate over long interaction histories face a practical tension: retaining enough context to answer questions about earlier configuration state while limiting the number of tokens sent to the model. Prior work has documented sensitivity to the position of relevant information in long contexts (Liu et al., 2023), and virtual context management has been proposed to manage memory across sessions (Packer et al., 2023). This pilot asks a narrow question: in a controlled synthetic setting, which history policy preserves configuration state while reducing API token use? We compare full history, a recent-window baseline, lexical retrieval, and retrieval with summaries. The full-history condition serves as an unbounded reference, not a deployable budget. The recent-window baseline tests whether recency alone suffices. Retrieval selects records by lexical overlap with the question, and retrieve_summary adds a summary of non-retrieved history. All policies use the same model and isolated sessions, and summary overhead is included in token accounting. The goal is not to introduce a new method or to claim benchmark validation, but to establish a cautious baseline for a reusable experiment pipeline.",

  "methods": "We constructed 24 deterministic synthetic histories with a fixed seed, comprising 60 records total. Tasks are grouped into three families: lookup, partial, and revision, with 8 tasks per family. Records are placed in early, middle, or late positions, yielding 9 early, 9 middle, and 6 late cases. Histories include field-wise overwrites to simulate configuration changes. Four policies are compared: full, recent, retrieve, and retrieve_summary. Full sends the entire unbounded history. Recent sends only the most recent records within a proxy budget of 512 tokens. Retrieve selects records by lexical overlap with the question, also within the 512-token proxy budget. Retrieve_summary adds a summary of non-retrieved history within a 256-token proxy budget. Token counts are proxy estimates using the cl100k_base tokenizer, not exact model tokens. All policies run with the same model, temperature 0, top_p 1, thinking disabled, and isolated sessions. The agent processes a supplied static history in a single answering call; these are not observed multi-turn interactions. History selection is applied in before_invoke, and actual calls are captured in after_model_call. Summary costs are included in token accounting. Scoring is exact match and field accuracy. Paired comparisons use exact McNemar tests, reported as exploratory and not corrected for multiple comparisons. Wilson intervals are descriptive only and are not guarantees.",
  "discussion": "The recent-window baseline fails on early and middle positions, consistent with omitted evidence rather than a general failure of recency. It is correct only on late-position cases, where the needed records fall within the recent window. Retrieve and retrieve_summary match full on every case in this synthetic sample, but this should not be read as equivalence. The tasks favor lexical matching because questions and records share identifiers, which may overstate retrieval performance relative to more paraphrased or ambiguous settings. Adding summaries does not improve accuracy over retrieval alone here, and it increases API calls and mean seconds per task, though total proxy tokens remain lower than full. The full-history reference is unbounded, so token comparisons are descriptive rather than budget-matched. Wilson intervals are wide and descriptive; they are not guarantees. The paired McNemar results are exploratory and uncorrected. This is a local synthetic pilot, not benchmark validation, and it does not establish real-world agent performance or long-context robustness. No novelty or equivalence claim is made.",
  "conclusion": "In this local synthetic pilot, lexical retrieval and retrieval with summaries preserved configuration state as well as an unbounded full-history reference on 24 tasks, while a recent-window baseline succeeded only on late-position cases. Summary overhead is included in token accounting, and all policies used the same model in isolated sessions. These findings are descriptive for a synthetic convenience sample; Wilson intervals are not guarantees, and paired tests are exploratory. The pilot contributes a reusable opt-in JiuwenSwarm rail and a verified experiment pipeline, but broader evaluation with held-out benchmarks, varied tokenizers, and real multi-turn interactions is required before any research claim.
