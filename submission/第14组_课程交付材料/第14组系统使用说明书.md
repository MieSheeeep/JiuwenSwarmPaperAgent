## 1. 系统概述与技术规格

### 1.1 系统简介
本项目是基于华为开源多智能体框架 **openJiuwen (0.1.16)** 与 **JiuwenSwarm** 研发的高可靠科研论文自主生成与闭环审稿系统。针对传统科研 Agent 容易生成“缺乏理论增量、实验对照失准、文本浅表改写、真实顶会打分低（普遍低于4.5分）”的严重痛点，系统深度重构了多智能体协作工作流，构建了 **“前门选题锦标赛 → 结构化事前验收协议 → Pilot小样本剪枝早停 → 顶会级4维量化审稿面板 → 实验级深层大修回路”** 的五重防御机制，实现了自主科研全流程的高可信、高质量和低算力开销。

### 1.2 软硬件运行环境要求
- **操作系统**：Windows 10/11 x64、Ubuntu 22.04 LTS 或 macOS (Apple Silicon / Intel)
- **Python 版本**：Python 3.12 或 3.13（推荐使用项目自带 `.venv` 虚拟环境）
- **内存建议**：8 GB RAM 或以上
- **存储空间**：至少保留 2 GB 可用硬盘空间（用于存储日志、合成数据集与生成的 LaTeX 编译产物）
- **网络连接**：运行在线大模型生成时需要可访问 LLM API 服务；系统完全支持离线探针与 Mock 仿真回归测试

### 1.3 技术栈依赖
- **核心多智能体基座**：`openjiuwen >= 0.1.16`
- **算法与数据处理**：`numpy`, `scikit-learn`, `scipy`
- **工程与自动化测试**：`pytest`, `python-docx`, `python-pptx`, `jinja2`
- **文档与编译支持**：`pdflatex` / `xelatex`（可选，系统内建纯 Python Markdown 与预编译模板渲染引擎）

## 2. 部署与环境配置

### 2.1 获取项目源码
```bash
git clone https://github.com/your-repo/JiuwenSwarmAgent.git
cd JiuwenSwarmAgent
```

### 2.2 虚拟环境配置
项目已在根目录下配置专用虚拟环境 `.venv`。如果需要重新初始化环境，可执行：
```powershell
# Windows PowerShell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 2.3 模型网关（Model Gateway）与密钥配置
系统支持无密钥本地运行（用于离线探针、剪枝测试与基准验证）。若需启用大模型驱动生成（`--enable-model`），请配置环境变量或创建 `config.yaml`：
```yaml
# config.yaml (请勿提交包含真实 API Key 的文件)
llm:
  provider: "deepseek" # 可选: deepseek, openai, qwen, siliconflow
  api_key: "sk-your-actual-api-key"
  base_url: "https://api.deepseek.com/v1"
  model: "deepseek-chat"
  temperature: 0.3
  timeout: 60
```
或通过 PowerShell 环境变量设置：
```powershell
$env:OPENAI_API_KEY="sk-your-actual-api-key"
$env:OPENAI_BASE_URL="https://api.deepseek.com/v1"
```

## 3. 系统核心架构与工作流全景

系统工作流由六大阶段（Stages）构成，由中央控制器 `AutonomousResearchOrchestrator` 与状态机引擎统一调度驱动：

```
+-----------------------------------------------------------------------------------+
|                            Autonomous Research Swarm                              |
+-----------------------------------------------------------------------------------+
|  [Stage 1: Literature]                                                            |
|    - TopicTournament 选题锦标赛 (多候选并行评估)                                 |
|    - TopicGate 理论增量与基线风险硬门禁                                           |
+-----------------------------------------------------------------------------------+
                                         |
                                         v
+-----------------------------------------------------------------------------------+
|  [Stage 2: Plan]                                                                  |
|    - StructuredAcceptance 结构化事前验收协议签署                                 |
|    - 预设 min_delta、效应量方向与池外基线压制红线 (OOP Domination Margin)          |
+-----------------------------------------------------------------------------------+
                                         |
                                         v
+-----------------------------------------------------------------------------------+
|  [Stage 3: Experiment (Pilot Gate)]                                               |
|    - Pilot 探针先行运行 (10%~20% 样本)                                            |
|    - PilotGate 三态决策:                                                          |
|        * go     -> 效果显著且战胜池外基线，放行进入完整大实验 (Full Experiment)   |
|        * pivot  -> 方差过大或基线边缘，自适应调整超参后复测                       |
|        * no_go  -> 效应量未达标或被池外弱模型压制，立即剪枝早停 (节约 >90% Token) |
+-----------------------------------------------------------------------------------+
                                         | (通过)
                                         v
+-----------------------------------------------------------------------------------+
|  [Stage 4: Review]                                                                |
|    - Cold Review: 事实一致性与基准泄露初筛                                        |
|    - ConferenceReviewPanel: ICLR/NeurIPS 顶会 4 维量化内审 (Soundness / Novelty / |
|      Significance / Empirical Thoroughness)                                       |
|    - DeepRevisionManager: 若分数低于 6.0 分发实验大修，触发补齐消融/补充对比基线   |
+-----------------------------------------------------------------------------------+
                                         | (合格)
                                         v
+-----------------------------------------------------------------------------------+
|  [Stage 5: Paper & Export]                                                        |
|    - WritingAgent: 基于严格实验实证撰写 ICLR 格式学术论文                         |
|    - 导出 paper.pdf, paper.tex, evidence.json, review_summary.json                |
+-----------------------------------------------------------------------------------+
```

## 4. 命令行执行（CLI）完全指南

系统所有核心指令统一使用 `.venv\Scripts\python.exe` 运行，确保依赖版本完全可控。

### 4.1 特征缺失实证研究（Missingness Study）
用于验证在复杂多模态/表格数据特征缺失条件下，探针自适应剪枝与自动回退能力。
```powershell
# 运行完整研究流程并输出到 output/missingness_run
.venv\Scripts\python.exe scripts/run_missingness_study.py --project output/missingness_run --enable-model --until export
```

#### 核心参数说明
| 参数项 | 类型 | 默认值 | 作用说明 |
| :--- | :--- | :--- | :--- |
| `--project` | 路径字符串 | 必填 | 实验工程工作目录，存储状态、产物及审稿报告 |
| `--enable-model` | 布尔开关 | False | 启用真实大语言模型生成（若关闭则使用离线内建探针引擎） |
| `--until` | 阶段枚举 | `export` | 执行终点阶段，可选：`literature`, `plan`, `pilot`, `experiment`, `review`, `paper`, `export` |
| `--auto-fallback`| 布尔开关 | True | 当主候选方案在 Pilot 阶段被剪枝时，自动无缝切换到锦标赛候选方案 2 |
| `--dry-run` | 布尔开关 | False | 空跑检查环境与配置文件语法完整性 |

#### 剪枝早停实况输出示例
当候选方案的均方误差（MSE）被池外现成模型（如 `HistGradientBoosting`）压制超过阈值（0.05）时，系统自动拦截：
```text
[PILOT GATE] Candidate MSE: 0.3901, Out-of-pool Best: 0.0498, Gap: 0.3402 >= 0.05
[PILOT GATE] Out-of-pool model 'HistGradientBoosting' dominates candidate!
[PILOT DECISION] Status: no_go -> Pruning pipeline early.
[ORCHESTRATOR] Saved 91.5% token budget (Tokens consumed: 8,531 vs Full: 100,000+).
```

### 4.2 结构化记忆与数字研究（Digits Study）
用于端到端走通无剪枝放行、全量实验、双层审稿及最终 ICLR LaTeX 编译导出流程：
```powershell
.venv\Scripts\python.exe scripts/run_digits_study.py --project output/digits_run --enable-model --until export
```
运行完成后，`output/digits_run/paper/` 目录下将生成：
- `paper.pdf`：标准双栏 ICLR 论文排版文档
- `paper.tex`：完整 LaTeX 论文工程源码
- `evidence.json`：全量实验可追溯证据链
- `review_summary.json`：顶会内审面板评分卡与详细审稿意见

## 5. Web 端交互式工作台（Workbench UI）操作指南

为了便于非技术评审人员、教师与合作开发者直观监控系统运行，系统集成了全功能可视化工作台。

### 5.1 启动工作台
在项目根目录下执行以下指令：
```powershell
.venv\Scripts\python.exe -m research.workbench.server --port 8080 --host 127.0.0.1
```
启动成功后，终端将输出：
```text
Serving Workbench Studio at http://127.0.0.1:8080
WebSocket live logs connected.
```
在现代浏览器（Chrome / Edge / Firefox）中访问 `http://127.0.0.1:8080` 即可进入交互控制台。

### 5.2 核心操作界面功能
1. **工作流画布（Workflow Canvas）**：
   - 动态点亮 6 个阶段节点，实时以绿（Completed）、黄（Running）、红（Pruned/Failed）显示状态；
   - 点击任一节点即可展开该阶段的输入入参、中间变量与产出文件。
2. **实时日志流（Live Event Stream）**：
   - 实时推送 Agent 之间的结构化 JSONL 消息与调用链；
   - 支持按阶段名称、告警级别（INFO, WARNING, GATE_TRIGGER）进行过滤筛选。
3. **审稿雷达图与评分看板（Review Dashboard）**：
   - 实时呈现内审面板的四维得分雷达图（Soundness, Novelty, Significance, Empirical Thoroughness）；
   - 展示 Reviewer 1 (Hard Scorer)、Reviewer 2 (Empirical Auditor)、Reviewer 3 (Significance Evaluator) 的分项批注。
4. **产物管理与一键下载（Artifacts Manager）**：
   - 可以在线预览渲染后的论文 PDF、图表结果 PNG、以及审稿修改计划；
   - 提供 ZIP 一键归档下载完整提交包功能。

## 7. 常见问题排查与 FAQ

### Q1: 在 Windows PowerShell 中运行时中文出现乱码怎么处理？
**解决方案**：系统各入口脚本均已内建 `sys.stdout.reconfigure(encoding='utf-8')`。若终端仍有乱码，请在 PowerShell 中先执行：
```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
chcp 65001
```

### Q2: 为什么运行 missingness 实验时，程序在 Pilot 阶段就停了，显示 `status: pruned`？
**解答**：这属于系统正常的高价值防御行为。系统检测到候选方案的 MSE 性能（0.3901）大幅落后于池外弱基线 `HistGradientBoosting`（0.0498），触发了事先在 `StructuredAcceptance` 中签署的池外压制红线。系统选择主动剪枝，避免在注定失败的研究方向上浪费数小时实验和数万 Token。如需强制走完全程，可适当调大 `--oop-domination-margin` 或使用 `--auto-fallback`。

### Q3: 运行大模型时出现 API 超时或网络抖动？
**解答**：`ModelGateway` 内建指数退避重试（Exponential Backoff，最大重试 3 次）。若持续超时，系统将自动降级使用本地确定性探针，确保研究流转不中断。
