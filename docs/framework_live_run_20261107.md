## 输入与实验

方向：有限上下文下的多跳问答文档选择。模型：deepseek-flash，通过 openJiuwen ReActAgent 和 JiuwenSwarm FrozenMessagesRail 调用。

自动下载 HotpotQA distractor 公开验证集的前 40 条，固定 seed 20261107 随机划分 8 道开发题和 32 道本地评估题。开发/评估是本项目划分，不是官方测试集。生成策略为 lexical_overlap_topk_with_floor，按问题词与正文/标题重合、词频及固定打破平局规则选择最多两篇文档；原始函数与哈希已保存。没有更改算法来提高已观察到的评估成绩。

## 真实运行暴露的问题

1. 生成方案最初超出解释器能力，出现未提供的嵌入模型设想。正式实验前重新约束了问题与方案。
2. 解释器缺少常见的集合运算、set.add 和循环解包；修复后复用已有模型响应。
3. 一篇较长文档触发过小的词列表上限；仅调整基础设施容量，保持生成源代码和冻结方法不变，并复用回答缓存。
4. 写作校验器不能接受带章节编号的标题；增加格式归一化，保留原模型文字。
5. 内部审查输出过长导致 JSON 截断；增加简短问题清单和局部修改流程。
6. 多次续跑暴露“本次运行段用量”与“完整实验用量”的区别；论文中间稿一度把 91 次/69,014 tokens 当成实验总量，修订稿已改为完整的 138 次/106,291 tokens。

所有失败响应、用量、恢复说明与原始版本保留在项目账本中；这次不是无人干预的一次成功运行，不能把人工修复框架的过程隐藏掉。
