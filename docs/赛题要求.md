# 赛题要求

> 说明：第一节至第三节为组内提供的赛题原文整理；第四节评分模型来自本组汇报材料中的赛题解读，属组内整理口径，非官方原文；第五、六节为本组对照说明。

## 一、赛题基本信息

- 赛题名称：**基于 JiuwenSwarm 的 Agent 科研论文自动生成**
- 出题方：**华为 openJiuwen 开源 AI Agent 社区**
- 技术底座：自研蜂群智能体架构（JiuwenSwarm）
- 聚焦方向：Agent 前沿技术

社区背景：openJiuwen 社区由华为 2012 实验室、华为云、昇腾、鲲鹏、小艺等多方能力联合构建，围绕 Coordination Engineering、Agent 全链路自演进、算力基础设施亲和等核心能力，孵化了 JiuwenSwarm、CodingAgent、DeepSearch 等代表性 AI Agent。已完成三项生产级部署：华为云办公智能体、中国邮政储蓄银行「PSBC-Claw」、中科大灵境造物。

## 二、赛题任务

开发智能体，完成比赛方指定 Agent 方向的科研短论文（Short Paper）**全流程/半流程自动化生成**，覆盖：

```
选题拆解 → 文献调研 → 方法设计 → 论文撰写 → 结果分析
```

要求输出符合学术规范的完整论文。建议使用 **ICLR 模板**生成论文，以便通过 **Stanford Agentic Reviewer** 平台进行论文自动化评测。

## 三、建议赛题主题（聚焦 Agent 关键技术）

1. Agent 上下文工程设计
2. Agent 记忆引擎设计
3. Agent 自演进

## 四、评分模型（组内整理口径）

| 考核方向 | 分值 | 要求 | 本组对应 |
|---|---:|---|---|
| 论文质量 | 60 | Stanford 评审 40 分 + 论文评测 Agent 20 分；英文论文、真实实验、证据检查 | 8 页 ICLR 论文；外部 Agentic Reviewer 4.9/5.0 |
| 框架贡献 | 15 | 代码、Skill、文档或补丁 | 三类 Rail 本地适配 + 29 项离线检查 + 补丁 |
| 系统能力 | 15 | 角色分工、任务调度、恢复与文档 | 11 阶段状态机、五类角色、中文工作台、恢复机制 |
| 资源控制 | 10 | API 调用、Token 与运行成本 | 预约—结算—对账、Token 账本、Pilot 止损 |

说明：该分值结构来自本组对赛题材料的整理，最终评分口径以官方发布为准。

## 六、本组的落地方式

赛题覆盖「全流程/半流程」两种口径。本组按**半流程基线**落地，覆盖其中两段核心能力：

1. **上下文工程**：把「历史证据怎么给模型」做成可插拔的 ContextBudgetRail，用配对实验量出策略差异与成本差异。
2. **证据约束写作**：论文只使用已落盘的实验结果，表格与数字由程序装配，模型只负责文字组织。

未覆盖：自主提出新科学假设、自主设计全新实验方向、替代同行评审。

## 七、口径约束

- 赛题原文由组内提供并整理，可能存在转述偏差，以官方赛题页面为准。
- 4.9/5.0 为 AI 评审估分，不代表 ICLR 录用，也不代表赛题总分。
- 框架贡献定位为「基于现有 AgentRail 接口的项目适配」，未提交上游 PR、未获官方合并、未验证通用性。
- 对外表述不使用「框架底层重构」「通用框架创新」「已被社区采用」等措辞。
