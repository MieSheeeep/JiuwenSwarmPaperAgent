## 第 2 页：赛题背景与自主科研 Agent 的工程挑战

### 【页面视觉呈现】
- **左侧：自主科研智能体的学术理想**
  - 多角色分工替代人工科研全周期（Literature → Plan → Experiment → Review → Paper）；
  - 大模型赋能科学发现，加速跨学科假设生成与验证。
- **右侧：严肃科研场景下的四大核心工程断点**
  - **断点 1：立项失控** —— 缺乏理论增量校验，极易生成缺乏实际贡献的同质化“水文”；
  - **断点 2：算力空耗** —— 缺乏事前验收与小样本早停，盲目跑满全量实验消耗海量 Token；
  - **断点 3：幻觉蔓延** —— 实验数据与论文正文脱节，结论无法穿透溯源至底层执行记录；
  - **断点 4：浅表修补** —— 收到外部审稿批评时仅做文本层面的 Prompt 润色，无法反向驱动实验设计迭代。

### 【逐字汇报讲稿】
> 近年来，以 AI Scientist 为代表的自主科研智能体引发了学界的广泛关注。但将其实际应用于严肃科研任务时，会迅速遇到四大严峻的工程断点：
> 
> 第一是**立项失控**：大模型倾向于生成看似宏大但缺乏理论增量（Theoretical Delta）的空洞选题；
> 第二是**算力空耗**：由于缺乏早期效能探测，方案即便显著落后于经典基线，依然会机械地跑满全量大实验，带来巨大的算力与 Token 浪费；
> 第三是**数据幻觉**：传统流水线中，写作 Agent 往往在缺乏约束的情况下凭空编造实验数据，破坏了学术研究的可复现性；
> 第四是**浅表修补**：面对同行评审意见，现有系统多停留于段落重写与修饰性润色，无法真正驱动实验设计的补强。
> 
> 本项目的核心使命，就是用严格的软件工程规范与自驱质量门禁，攻克这四大断点。

## 第 6 页：前门选题与研究规划：假设空间参数化

### 【页面视觉呈现】
- **选题量化评分公式**：
  $$Score = 0.35 \times \Delta_{theo} + 0.25 \times S + 0.25 \times N - 0.15 \times R_{base}$$
  - $\Delta_{theo}$：理论增量（相对于基准算法的机制创新度）
  - $S$：学术重要性（对核心瓶颈的解决价值）
  - $N$：新颖性（相较近 3 年前沿工作的差异度）
  - $R_{base}$：基线风险系数（被简单基准击败的潜在概率）
- **假设形式化映射表**：
  - 将定性的学术猜想转化为可证伪的参数集合；
  - 明确自变量（模型变体、上下文选择策略）、因变量（准确率、MSE、F1）、控制变量（硬件环境、随机种子集合）。

### 【逐字汇报讲稿】
> 针对传统系统“盲目开题”的顽疾，我们在规划阶段引入了形式化的前门量化模型。
> 
> 系统拒绝无边界的模糊立项，而是从理论增量、学术重要性、新颖性与基线风险四个维度对候选方案进行加权评分，设立 6.0 分准入门禁。
> 
> 更关键的是，系统在进入实验前必须完成“假设空间的参数化”：明确将自然语言的学术假设映射为严格的数学自变量、因变量与控制变量。例如在上下文记忆研究中，严格规定比较集合为“全量历史、滑动窗口、检索机制以及检索摘要混合”，并将度量指标锚定为绝对准确率与 Token 开销比。这一机制从源头上阻断了不可检验伪科学假设的产生。

## 第 7 页：结构化事前验收协议 (StructuredAcceptance)

### 【页面视觉呈现】
- **事前验收契约核心字段（`StructuredAcceptance`）**：
  ```json
  {
    "task_id": "context_selection_v2",
    "primary_metric": "accuracy",
    "metric_direction": "maximize",
    "min_delta": 0.05,
    "max_acceptable_variance": 0.02,
    "oop_domination_margin": 0.05,
    "out_of_pool_baselines": ["HistGradientBoosting", "RuleBasedWindow"]
  }
  ```
- **三道防伪技术红线**：
  1. **锁死效应量方向**：严禁在观测到实验异常后随意掉包优化目标；
  2. **锚定最小效应增量（`min_delta`）**：微不足道的随机抖动不能包装为算法创新；
  3. **引入池外基线压制约束（`oop_domination_margin`）**：若新方法无法显著超越未微调的开箱即用传统模型，强制裁定实验无效。

### 【逐字汇报讲稿】
> 现代软件工程推崇“测试驱动开发”，而严肃科学研究必须奉行“预注册（Pre-registration）”。为了杜绝 AI 科研中常见的“先射箭后画靶心”与选择性报告（p-hacking），我们在系统中引入了 `StructuredAcceptance` 结构化事前验收协议。
> 
> 在实验代码启动之前，规划智能体必须与环境签署数据契约，白纸黑字锁定四个核心参数：
> 其一是最小效应量 `min_delta`，明确新算法相较于 baseline 必须达到的绝对超越下限；
> 其二是指标极性，锁定优化方向；
> 其三是最大容许方差比，防范种子漂移假象；
> 其四是开创性地引入了池外基线压制红线。这保证了所有实验产出都在防作弊的严密监督下进行。

## 第 8 页：实验适配执行与可穿透追溯证据链 (Evidence Artifact)

### 【页面视觉呈现】
- **可穿透追溯证据链架构图**：
  - `Raw Execution`: Python 运行时沙箱、真实计算输出、模型调用哈希；
  - `evidence.json`: 结构化沉淀指标明细、样本级得分、各轮 API Token 账单；
  - `paper.tex / Table`: 论文表格中的每一个数字直接关联底层数据记录指针。
- **数据流闭环特征**：
  - **Append-only**：运行日志只允许追加，严禁覆写篡改；
  - **Zero-Hallucination Gate**：写作智能体渲染表格与正文时，必须通过正则断言比对 `evidence.json`，阻断数字虚构。

### 【逐字汇报讲稿】
> 传统科研 Agent 生成论文最令人诟病的就是“数据幻觉”：正文写着性能提升了 15%，翻开实验日志却查无实据。
> 
> 为此，我们构建了一套可穿透溯源的 Evidence 证据体系。实验适配器在沙箱中调度真实代码运行，每一次推演与评测都会生成唯一的执行哈希，并落盘至无锁追加的日志文件中。
> 
> 最终汇聚成的 `evidence.json` 不仅记录了宏观均值，更保留了样本级明细与 Token 消耗审计。写作智能体在组织论文时，被强制剥夺了直接编写浮点数的自由，所有正文指标必须通过模板插值从证据链中提取，并经由校验器核验。这实现了科研成果在代码层面的 100% 可复现与可审计。

## 第 10 页：顶会级双层审稿体系：事实初筛与 4 维量化内审

### 【逐字汇报讲稿】

## 第 11 页：4 维评审指标与硬底线裁决机制 (Hard Floor)

### 【页面视觉呈现】
- **ICLR 4 维评审量化打分模型（满分 10.0）**：
  | 评审维度 | 权重 | 核心考察点 | 硬底线拒稿红线 |
  | :--- | :---: | :--- | :---: |
  | **Soundness** | 30% | 数学推导严谨性、论证逻辑闭环度、控制变量严格度 | **< 5.0 票决拒稿** |
  | **Novelty** | 25% | 相对于近 3 年前沿工作的理论贡献与机制差异 | **< 5.0 票决拒稿** |
  | **Significance**| 20% | 实验结论对领域研究的启发价值与实践指导意义 | **< 5.0 票决拒稿** |
  | **Empirical Thoroughness** | 25% | 消融实验完备性、基线覆盖面、统计显著性与误差界 | **< 5.0 票决拒稿** |
- **加权总分裁决标准**：
  - $\ge 7.0$：Clear Accept（直接进入交付）
  - $5.5 \sim 6.9$：Weak Accept / Borderline（触发大修回路）
  - $< 5.5$ 或触发任意硬底线：Reject（拒稿重置）

### 【逐字汇报讲稿】
> 在内审面板的标准设定上，我们严密对标了 ICLR 与 NeurIPS 的官方审稿规范，拆解为四大核心维度：
> 
> Soundness 考察技术与逻辑自洽性；Novelty 评估理论增量与独特性；Significance 衡量学术价值；Empirical Thoroughness 评估实证的充分程度。
> 
> 与市面上常见的模糊打分智能体不同，我们设立了极具约束力的 **Hard Floor（硬底线拒稿机制）**：哪怕论文综合得分看起来尚可，但只要在 Novelty 或 Empirical 等关键维度跌破 5.0 分，系统便无条件触发一票否决。这确保了系统绝不产出“文字优美但内质空洞”的平庸成果。

## 第 12 页：评审反馈驱动的深层大修回路 (DeepRevision 实验级修补)

### 【页面视觉呈现】
- **对比示意：浅表修补 vs 实验级深层大修**：
  - **传统模式（浅表修补）**：Reviewer 指出“缺少消融” → 重新调用 LLM Prompt 重写段落 → 掩耳盗铃，实验依旧缺失。
  - **本项目模式（`DeepRevisionManager`）**：
    1. 解析 Reviewer Weaknesses 提取结构化缺陷描述；
    2. 生成包含具体修复指令的 `RevisionPlan`；
    3. 自动向 `ExperimentAgent` 派发追加消融实验与补充基准任务；
    4. 执行补测后更新 `evidence.json`，再交由写作层重构实证章节。

### 【逐字汇报讲稿】
> 面对审稿人提出的负面意见，传统的科研 Agent 往往只是简单地把批评意见作为上下文塞给大模型，让其重写引言或结论，这在学术上属于典型的掩耳盗铃。
> 
> 本项目研发了 **DeepRevisionManager（实验级深层大修系统）**。当内审专家指出“缺乏关键模块的剥离验证”或“未与强基准对比”时，系统会将该 Weakness 自动转化为形式化的实验维修工单。
> 
> 调度引擎会自动唤醒实验智能体，在沙箱环境中动态补齐对应组件的消融计算，并将新生成的对比曲线追加注入证据知识库。随后，撰写模块基于充实后的全新实验数据重新绘制图表、更新正文论述。这种以真实代码和实验为支点的深层修复，实现了真正意义上的自主科研自我进化。

  - **`no_go`（主动剪枝早停）**：检测到候选方法被池外弱基准压制，立即终止并释放算力。
- **算力收益量化对比（基于特征缺失实测数据）**：
