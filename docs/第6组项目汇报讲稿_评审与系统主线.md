## 第2页 赛题背景与任务要求

### 页面内容

**利用 Agent 完成科研任务并形成论文**

- 科研工作包括文献调研、研究问题、方法设计、实验、分析与写作。
- 系统需要组织这些工作的执行和协作。
- 提交成果涉及论文、Agent源码、设计文档、资源报告与框架贡献。

### 讲稿

赛题以科研论文生成为应用场景。系统需要处理的工作包括查阅已有研究、提出问题、设计方法、运行实验、分析结果，以及论文写作和修改。

这些工作有前后依赖。例如，研究问题决定实验要验证什么；实验结果决定论文可以作出什么结论；审查发现问题以后，还需要回到相应步骤进行修改。

因此，我们需要设计一个能够组织研究工作的 Agent 系统，并通过源码、文档和实际产物说明它怎样运行。

另外，我们还要把 Agent 系统设计好，准备清楚、可用的设计文档，并按要求提供源码，让评审能够了解和检查实现。运行时需要考虑模型调用的 Token 消耗和成本，同时提供资源报告。框架贡献也要落到具体的代码、Skill、文档或补丁上。

所以，后续设计既要考虑研究质量，也要考虑系统能否实际执行、是否方便检查，以及运行成本。

## 第4页 外部评审暴露了什么问题

### 页面内容

**一次按 ICLR 标尺进行的外部AI评审：4.4 / 10**

案例：缺失率变化条件下的表格回归模型选择。

评审认可：

- 推导正确，实验过程透明。
- 对结果和限制的说明较清楚。

主要不足：

- 核心代数已有，研究贡献有限。
- 数据集和方法范围较窄。
- 训练缺失率固定，缺少更充分的敏感性分析。

### 讲稿

我们实际生成过一篇关于缺失率变化下模型选择的论文，并拿到了按 ICLR 标尺给出的外部AI评审，估分是4.4分。

评审认可推导和实验的透明性，但认为主要结论建立在已有代数上，方法贡献不够充分。实验只覆盖几个较小的数据集，训练条件也比较固定，因此不足以支持更广泛的意义。

这个反馈说明，文章写完整、实验能复现以后，仍然可能存在研究问题和实验设计上的不足。后面的改进需要从这些工作入手。

页面脚注：该分数为用户提供的外部AI评审估分，不是ICLR会议评审决定，也不是比赛总分。

## 第5页 我们据此改了什么

### 页面内容

**把研究质量的检查放进工作流**

| 评审暴露的问题 | 系统中的对应设计 |
|---|---|
| 问题和贡献不清楚 | 规划阶段明确假设、与已有工作的关系和验证方式 |
| 实验比较不充分 | 设计阶段保存基线、消融、指标、数据划分和预算 |
| 审查停留在文字意见 | 增加分角色评审、逐项裁决和修改目标 |
| 修改以后结果与正文不一致 | 按阶段维护依赖和版本，更新受影响产物 |

### 讲稿

针对这些问题，我们把改进落实到工作流的几个位置。

在研究规划阶段，要求把问题、假设和验证方式写清楚；在实验设计阶段，明确比较哪些方法、需要哪些消融、使用什么指标和预算。

论文生成以后，由不同评审角色检查方法、实验和意义，再给出具体问题和处理决定。修改时，系统记录哪些阶段受到影响，避免新方案继续沿用旧结果。

这些设计已经形成对应模块。下面会分别说明哪些已经接入当前流程，哪些属于需要显式调用的扩展。

## 第6页 Agent协作架构

### 页面内容

**中央调度器与研究角色协作**

- 文献Agent：检索和比较已有工作。
- 研究规划Agent：提出问题，形成方法和实验方案。
- 方法实现Agent：生成当前支持范围内的方法代码。
- 论文写作Agent：根据方案和结果组织英文论文。
- 审查角色：进行事实检查和研究质量评价。
- 裁决模块：处理问题、评分和修改决定。

调度器管理阶段、共享产物、预算和执行状态。实验、统计和编译由工具或服务完成。

### 讲稿

系统以任务调度器连接不同角色。文献Agent提供已有工作的资料，规划Agent形成可执行的问题和方案，实现Agent完成当前支持的方法代码。

实验程序运行以后，分析服务计算结果，写作Agent据此组织英文论文。论文再进入审查，由事实检查和研究质量评价给出问题，裁决模块形成通过、修改或停止的决定。

当前这些角色主要使用同一个模型后端，在不同阶段和上下文中执行，通过保存的产物协作。调度器、实验程序和统计服务有各自的职责。

## 第7页 文献与研究规划具体做什么

### 页面内容

**从研究方向形成可以检验的方案**

文献阶段交付：来源、阅读范围、方法比较和局限。

规划阶段交付：

- 研究问题和假设。
- 相对于已有工作的具体差异。
- 对照方法和评价指标。
- 什么结果支持假设，什么结果说明假设不成立。

扩展：多候选方案比较与备选管理。

### 讲稿

文献阶段要提供真实来源，并说明阅读的是摘要还是正文片段。规划阶段在这些材料基础上提出假设，再明确怎样通过实验判断。

这里需要做的是找到值得验证的问题，并把实验做清楚。已有相关工作需要认真比较，它们可以成为基线和方法依据。

项目也实现了多候选方案的比较与备选管理模块，用于检查方法差异、可行性和比较风险。不过它是可选扩展，不能把它说成每一次默认运行都已经执行的步骤。

## 第8页 实验设计与小规模检查

### 页面内容

**正式运行前保存实验方案**

必须明确：

- 数据来源和开发、测试划分。
- 新方法、固定基线和所需消融。
- 指标、比较条件与解释范围。
- 调用预算和停止条件。

小规模检查用于发现接口、格式和执行问题。不同实验插件可以提供不同诊断。

### 讲稿

研究问题明确以后，需要把实验方案保存下来。包括使用哪些数据、怎样划分开发和测试、比较哪些方法、用什么指标，以及允许消耗多少资源。

正式实验之前，还要进行小规模检查。以当前问答配置为例，这一步主要检查方法接口和输出格式，不能把检查通过理解成方法已经有效。

框架也支持其他实验插件提供诊断，以及可选的继续、调整和停止决策。具体采用什么标准，需要由对应研究任务给出。

## 第9页 方法实现与真实实验执行

### 页面内容

**模型提出方法 程序执行和测量**

- 已接入问答任务支持生成 `select(question, passages, budget)`。
- 代码通过受限解释器检查后执行，保存源码和版本。
- 实验适配器提供 `prepare / pilot / run / analyze`。
- 保存原始回答、指标、调用记录与实际用量。

### 讲稿

方法实现Agent目前可以在支持的任务范围内生成实际代码。例如问答配置中，它可以生成文档选择函数，决定给回答模型提供哪些文档。

代码需要通过接口、返回值和操作范围检查，再交给实验适配器运行。实际执行、回答评分和指标计算由程序完成，原始结果和模型用量都会保存下来。

对于图像分类、缺失数据等任务，我们使用对应实验插件。新的领域如果没有适配器，还需要补充实验实现。

## 第10页 面向ICLR论文的英文写作

### 页面内容

**英文论文结构与LaTeX工程**

- 组织摘要、引言、相关工作、方法、实验、结果、讨论和局限。
- 先生成提纲，再根据研究方案和结果生成正文。

- 核对引用、章节和分析版本。

### 讲稿

论文写作使用英文，并按照机器学习研究论文的结构组织内容，包括问题背景、相关工作、方法、实验和局限。

写作分为提纲和正文两个步骤。输入材料包括已经保存的方案、分析和真实文献，数值表格和图表依据实验结果生成。

最后装配为LaTeX工程，使用ICLR风格模板编译PDF，保留源码，便于继续修改。格式是写作交付的一部分，论文是否有贡献、证据是否充分，需要由后面的评审检查。

## 第11页 ICLR导向的研究质量评审

### 页面内容

**ConferenceReviewPanel**

三类内部审稿角色：

| 审稿角色 | 重点 |
|---|---|
| 理论与创新视角 | 方法是否正确，与已有工作的差异是否充分 |
| 实验视角 | 基线、数据范围、效果大小与实验对照 |
| 应用视角 | 假设是否现实，结果是否有实际意义 |

输出：评分、优点、缺点、问题和风险提示。

### 讲稿

针对外部评审指出的不足，我们实现了ConferenceReviewPanel，用不同角色检查论文的研究质量。

第一类角色关注理论正确性和创新性；第二类关注实验设计、比较方法和效果；第三类关注假设与应用意义。

每个角色都要给出具体意见和分项评分，而不只是说论文写得好不好。代码中的角色提示参照ICLR、NeurIPS等会议的评审关注点；这些仍然是项目内部的模拟评审结果。

## 第12页 四维评分与裁决规则

### 页面内容

**内部评审怎样形成处理决定**

四个分项：

- Soundness：技术可靠性。
- Novelty：新颖性。
- Significance：研究意义。
- Empirical Thoroughness：实验充分性。

同时记录Overall。代码设置分项与总体阈值，形成 `accept / revise / stop`。

### 讲稿

内部评审从可靠性、新颖性、研究意义和实验充分性四个方面评分，同时给出总体分数。

裁决模块汇总各角色的评分和问题，并根据项目设置的阈值形成决定。当前实现中，可靠性、新颖性和意义低于5分，或者总体低于6分，会触发停止规则；满足条件后再区分通过和修改。

这些阈值是我们实现的内部控制规则，需要根据实际效果继续检查。它们不能代替外部评审，也不能证明论文已经达到ICLR录用水平。

## 第13页 事实审查与研究质量评审怎样配合

### 页面内容

**分别检查结果是否可信 研究是否有价值**

事实与证据审查：

- 结论支持、方法正确性、比较公平性。
- 可复现性与研究意义。
- 读取明确的稿件和支持材料，逐项裁决问题。

研究质量评审：

- 从理论、实验、应用视角给出意见和分数。
- 形成继续修改、通过或停止的建议。

### 讲稿

系统中有两类相关但不同的审查。

冷审查会使用新的上下文，只读取明确提供的稿件和证据，重点检查结论是否有依据、数字和方法是否一致、比较是否公平。每个问题还要进一步判断是否成立。

会议导向评审则从研究质量角度看问题，例如方法贡献是否足够、实验范围是否支持论文意义。

在接入的通用配置中，两类结果会一起影响处理决定。它们使用同一配置后端，并不等于多个独立模型或真正的会议审稿人。

## 第14页 审稿意见怎样变成修改任务

### 页面内容

**区分文字修订 分析修订与实验补充**

| 问题类型 | 对应工作 |
|---|---|
| 引用错误、描述不清 | 核对来源，修改正文 |
| 指标或统计问题 | 重算分析，再更新论文 |
| 缺少基线、消融或参数范围 | 制定实验补充计划，重新执行相关步骤 |
| 研究贡献不足 | 重新判断研究问题和方法，决定是否继续 |

扩展模块：`DeepRevisionManager`。

### 讲稿

审稿意见需要被分解成具体工作。引用和描述问题可以修改文字，统计问题需要回到分析；如果缺少基线、消融或者参数范围，就需要补充实验。

项目实现了DeepRevisionManager，用于识别这类意见，形成文字和实验修改计划，并提供补充结果的合并功能。

目前它属于修改规划扩展，不能说已经在默认流程中自动完成所有补充实验。已接通的自动修订主要覆盖分析和写作；更早阶段需要显式重新打开，再由对应实验工具执行。

## 第15页 用外部评审说明工作流应该怎样响应

### 页面内容

**以4.4分论文的评审意见为例**

| 评审意见 | 工作流需要安排的任务 |
|---|---|
| 已有代数应用，贡献有限 | 回到问题和方法，说明研究增量及其依据 |
| 只有少量小型数据集 | 规划更广的实验范围，检查方法适用性 |
| 训练率固定 | 增加训练条件与部署条件的敏感性设计 |
| 缺少更广泛的稳健性比较 | 补查相关方法，确定适当基线和对照 |

### 讲稿

回到前面的外部评审。对于“贡献有限”，工作流需要重新检查研究问题和方法，不能只让写作角色换一种表达。

对于实验范围和训练率固定的问题，需要由研究规划和实验模块安排新的条件，并在预算允许时执行。相关工作和比较不足，则要回到文献和基线设计。

这一页说明的是评审意见应怎样分配到各个步骤，并不表示这篇论文的所有问题都已经得到解决。我们希望通过这样的分工，让下一次研究从更早阶段就考虑这些要求。

- 比较固定top-2、全部文档、自适应扩展和生成策略。

审查没有直接放行，而是指出开发与测试描述不一致、验收条件表述和引用归属等问题，要求退回写作。这说明任务执行和问题反馈能够留下具体产物；生成方法本身的效果还要单独评价。

## 第17页 实验结果与质量判断

### 页面内容

**系统执行成功与研究方法有效需要分别评价**

32题样本：

| 方法 | 正确题数 |
|---|---:|
| 固定top-2 | 14/32 |
| 全部文档 | 14/32 |
| 自适应top2到top4 | 17/32 |
| 生成的词项策略 | 4/32 |

生成策略没有优于基线，草稿仍需要修订。

### 讲稿

这次运行中，生成的词项策略只答对4题，低于其他三个比较方法，因此没有支持它改善准确率。

这个结果也让我们区分了两件事：系统是否执行了研究，和提出的方法是否有效。前者可以通过源码、调用和产物检查，后者必须看实验结果。

系统需要保留这样的失败结果，让分析和论文如实报告。后续可以根据问题继续改方法，也可以停止这个方向，不能把负面结果改写成性能提升。

## 第18页 根据另一轮评审补充了哪些验证

### 关于ICLR的表述

- 本项目使用英文论文结构、ICLR风格LaTeX模板，并实现会议导向的内部评审。没有将任何产物描述为ICLR已投稿、已录用或正式会议评审通过。
- 第4页4.4/10来自用户提供的缺失数据论文外部评审，按ICLR标尺校准。另一篇历史记忆论文有4.5/10记录，二者不合并成同一论文的评分变化。
- 内部模拟评审、外部AI评审、比赛评分、会议正式评审分别表述。内部规则和提示词不称为已获官方校准。
- 代码中的分项阈值为小组设置，不能称为ICLR官方录用阈值。源码总体低于6也会停止，不能笼统说“所有项低于5才停止”。

### 关于自动执行范围

- `ConnectedProfile`接通研究各阶段，其review阶段组合冷审查与可配置的ConferenceReviewPanel。
- 冷审查自动修订目标是writing或analysis；更早阶段可由Workflow显式invalidate/reopen。
- `DeepRevisionManager`提供意见分类、修改规划与结果合并。当前未发现它在默认ConnectedProfile中自动调用的证据，因此不能声称默认流程会自动追加全部基线、消融或数据集。
- `TopicTournament`及备选回退有代码与测试，但不是默认CLI必经步骤。候选审查应该服务于确定可验证的研究问题，不把“有相关工作”说成禁止实验的理由。
- 单后端不同角色不等于多个独立模型。不同Profile的审查配置也不完全相同，不能说每篇论文都经过相同评审路径。

### 关于完成情况

- 代码具备接口、已有测试、真实调用已运行、外部结果已返回，是不同层次的证据，需要分别说明。
- 不沿用历史第14组材料中的成员、工时比例、7分以上成绩、首次提出或大幅节约等未经核实的说法。
