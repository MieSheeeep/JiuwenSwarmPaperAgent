# Open Research Skills 接入

本次把技能接入项目自己的模型调用，而非仅安装到 Codex。正常使用 ConnectedProfile 运行时会自动生效；不需要额外配置 DeepSeek API。

来源：https://github.com/gxCaesar/open-research-skills

固定版本：`c79bac60f882b626e1754bff95101441e165e4ec`。三项技能及其完整配套资源保存在 `research/skillpacks/open-research-skills`，共 153 个上游文件，保留 Apache-2.0 LICENSE、NOTICE 和 THIRD_PARTY.md；上游文件逐字节保留，来源与 SHA-256 记录在 manifest.json。

## 实际接入点

| 阶段 | 技能 | 程序行为 |
|---|---|---|
| 文献、问题、方案 | research-publication-pipeline | 给相应模型调用加载 SKILL.md 和 survey-and-planning.md；要求明确搜索边界、可证伪问题和资源限制 |
| 结果交接 | 本地复算与证据清单 | analysis 生成带实验哈希的观测指标清单；未验证的假设和新颖性单列，不把负结果包装成改进 |
| 写作与修订 | prepare-conference-manuscripts，以及科研交接参考 | 加载写作/修订所需原文；额外提供实际 dev/test 样本数、条件数、完整实验调用与 token 总数 |
| 内部评审 | run-cold-review-panel | 五次全新上下文，分别检查论据、方法、公平比较、可复现性、研究意义；再用一次调用逐项裁决 |
| 导出 | 本地交付服务 | 打包固定技能资源、许可证、使用记录和本轮评审材料，供解压后复查 |

ConnectedProfile 是完整接入入口。通用 AgentExecutor 也加载对应阶段指导，但其通用工具循环不等同于 ConnectedProfile 的六次冷审查；需要自行注册实际执行工具。

只加载当前阶段需要的资源，不会把整个技能库塞进每次问答。实验中的问题作答不加载这些技能，避免改变被比较方法的回答条件。原项目的调度、预算、实验适配器、模板与输出格式继续控制执行；技能不会自行发起新实验或提交。

## 冷审查记录与边界

每轮生成独立 `cold_reviews/<round>/`，保存论文、明确选出的分析材料、实际文件清单/字节数/修改时间/哈希、五份意见、执行日志和最终裁决。模型只获得论文正文与引用条目、公开实验协议、选择器源码（如有）、已保存答案和指标，不带作者规划、历史讨论、前轮评语或调用账本。每个视角使用新的消息列表，没有工具权限访问作者工作区；这是输入上下文隔离，并非操作系统沙箱。

五个视角使用当前配置的同一个模型后端，明确记录这一点。它们不是五个不同模型，也不能代替真实同行评审。汇总审查必须把每个问题标为 confirmed / unsupported / underdetermined，并说明理由；未解决的重大问题不能判为 accept。不会通过投票把误判自动变成事实。

实际执行的是独立目录里的 `python -I replay.py`，使用标准库检查 task × method 完整性，重算保存答案的 EM、F1 和汇总指标，记录原始 stdout/stderr、退出码、Python/平台和耗时。执行失败强制退回 analysis。导出包包含此分析复算材料。

**它验证保存答案的计分与汇总，不重新调用模型，不验证完整检索过程，不等同于全套环境安装复现。** 文献引用在冷审查中只有论文提供的条目，未提供全文的内容核验仍应记为证据不足。当前阶段读的是结构化稿件；最终 PDF 的排版与人工视觉审查仍由原来的导出流程处理。

## 运行与费用

离线校验所有本地技能文件，不读取 API 配置、不调用模型：

```powershell
.venv/Scripts/python.exe -m research.workflow.skillpack
```

新的真实运行仍需原来显式的 `run --enable-model`。写作提示会变长；一次完整评审现在是五次视角调用加一次汇总，**共六次模型调用**，不是六位人工评委。所有调用继续受原有总调用数与 token 预算控制。预算不足会停止，不会绕过限制。恢复旧运行时，已完成且有效的阶段沿用已有产物；未来执行的阶段采用接入后的规范，旧论文不会被自动重写或追认为已接受新审查。

`skill_usage/*.json` 记录按调用标签加载的版本与文件哈希；`skill_calls/*.json` 将成功返回的模型调用 ID 与版本、资源、系统提示哈希对应起来。记录不含 API Key。

本次只执行离线集成验证，包括注入假模型走完整流程、实际执行保存答案复算、检测被篡改的技能与分数、解压交付包后在包内重新校验资源。**没有重新生成论文、没有新增付费调用，也没有证明论文质量或实验成绩提高。**

## 更新方式

不随远程 main 自动更新。需要更新时先审查上游新版本，调整 `scripts/vendor_research_skills.py` 与加载器的固定版本，再从对应干净 checkout 导入。导入器拒绝覆盖已被本地改动的资源。新版本应单独评估，不用旧版调用或论文证明其效果。

上游 ICLR 适配资料的示例年份与本项目历史 ICLR 2026 模板不同，因此本次不自动加载其 ICLR 2027 规则。采用会议版式不代表已经符合当前正式投稿政策，也不代表已在任何会议提交。
